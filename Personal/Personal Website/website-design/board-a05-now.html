Current Works — the /now sheet

A calm workbench snapshot: what's on the bench right now. A short load-path spine carries 2–3 current focuses; the one that's live pulses like a held current. A last updated stamp dates the sheet. One animated element, nothing more.

01 · Look & feel — live

The spine and nodes plot on once, in order. Then exactly one node — the active focus — breathes via a sine pulse. Light Direction A, IBM Plex type, faint blueprint grid, a thin under-construction hatch strip.

02 · What it means

  • The spine — a short vertical column line. Current focuses are loads hung off it, top to bottom — the same load-path language as the hub, scaled down to a quiet list.
  • The nodes — each focus is one node. Hollow nodes are steady, ongoing work; the single filled node pulses — that's where the current is flowing today.
  • The stamp — a dimension line plus a LAST UPDATED date. It admits the page is a snapshot, not a monument — an honest /now page.
  • The hatch strip — a faint engineer's "under construction" mark. Things here are in progress, by design.
Why one pulse, not four: restraint reads as confidence. A single breathing node says "this is the live one" without a dashboard of blinking lights. The rest of the sheet stays still — calm by default, motion only where it carries meaning.

03 · How it draws & loops — the algorithm

A one-shot plot-on intro, then a single requestAnimationFrame sine loop on the active node only. Everything else is static after the intro.

// 1 — THE CURRENT FOCUSES  (editable; top → bottom on the spine)
items = [
  { tag:"ONGOING",     text:"Building enterprise contact-centre products at CTINT", active:false },
  { tag:"PROTOTYPING", text:"Prototyping app ideas (see Concept Sketches)",        active:true  },
  { tag:"LEARNING",    text:"Deeper motion / GSAP + edge architectures",           active:false },
]
spine = { x:90, top:210, gap:64 }     // short vertical column line
nodeY = (i) => spine.top + i*spine.gap // each focus = a load hung off the spine

// 2 — INTRO: "PLOT ON", don't fade  (the shared signature motion)
timeline:
    spine.draw(0.5s)                      // dashoffset L → 0, plotter-style
    for (item, i) in items:
        node[i].popIn(at = 0.45s + i*0.18s)  // nodes appear in order
        label[i].fadeIn(same beat)
    then → start pulse() on the ONE active node

// 3 — THE PULSE  (sine wave on radius + opacity; active node only)
const rBase = 7, rAmp = 2.4, period = 2.4s
function pulse(now):
    phase = (now / period) * 2π
    s     = (sin(phase) + 1) / 2            // 0..1, smooth
    activeNode.r       = rBase + rAmp * s   // gently swells
    ring.r             = rBase + 6 + 10 * s // outer ring expands…
    ring.opacity       = 0.5 * (1 - s)      // …and fades as it grows
    requestAnimationFrame(pulse)            // the only running loop

// 4 — RESPECT THE USER
if prefers-reduced-motion:
    render one static frame (spine + all nodes drawn, active node at rBase)
    skip the pulse loop entirely
The "draw" primitive (reused everywhere): L = path.getTotalLength(); dasharray = L; dashoffset = L → 0. The spine here plots on with the exact three lines used by the hero spine, the Journey tower and every dimension line — so the /now sheet feels drawn by the same hand. The pulse is the only departure: not a fade, a held breath on the live node.
