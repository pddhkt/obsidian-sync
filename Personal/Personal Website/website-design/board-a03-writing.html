02 · What it means

  • Field notes, not blog posts — writing is framed as observations from the work: build logs, essays, product notes. Honest, dated, specific.
  • The datestamp — a mono annotation in the margin, like a surveyor logging when a reading was taken. It signals these are entries in a running record.
  • The category tag — one chip (Build notes / Essay / Product) so the index is scannable at a glance, no taxonomy overhead.
  • The dimension-line divider — the gap between entries is literally measured: a line with end ticks and a centred label. It's the structural metaphor doing the quiet work of a separator.
Why this works for Writing: the chrome stays in the engineer's drawing-set language — ruled margin, datestamps, measured gaps — while the content leads with software and product. The list scans like a contents sheet, and every divider reminds you a careful hand laid it out.

03 · How it draws & loops — the algorithm

Two moving parts: dividers draw on via the shared plotter primitive; entries reveal on a staggered timeline (an IntersectionObserver would gate this on scroll in production).

// 1 — THE DATA  (real field-note entries, newest first)
entries = [
  { title:"Automating structural calculations with Python + SAP2000", cat:"Build notes", date:"2026" },
  { title:"Shipping a cross-border app on Cloudflare + Convex",     cat:"Essay",       date:"2026" },
  { title:"Designing a TTS portal with version control",            cat:"Product",     date:"2026" },
  { title:"From load paths to data flows",                          cat:"Essay",       date:"2026" },
]   // between every pair of entries → one dimension-line divider

// 2 — BUILD A DIMENSION-LINE DIVIDER  (line + 2 end ticks + centred label)
function divider(label):
    line  = svg.line(x1:0, x2:W, y:mid)        // the measured span
    tickL = svg.line(x:0,  y:mid-5 .. mid+5)    // left end tick
    tickR = svg.line(x:W,  y:mid-5 .. mid+5)    // right end tick
    box   = svg.rect(centred) + svg.text(label) // "GAP · 24 mo" style tag

// 3 — THE SHARED "PLOT ON" PRIMITIVE  (every animated line uses this)
function plotOn(path, dur):
    L = path.getTotalLength()
    path.style.strokeDasharray  = L
    path.style.strokeDashoffset = L            // start hidden
    path.style.transition = "stroke-dashoffset " + dur + " ease-out"
    path.style.strokeDashoffset = 0            // → draws on like a plotter

// 4 — INTRO TIMELINE  (entries fade-up, dividers extend from centre)
function intro():
    reset(); forceReflow()
    for i, entry in entries:
        at = i * 160ms
        after(at):     entry.style = fadeUp(.5s)     // translateY(14)→0, opacity→1
    for i, div in dividers:
        at = i * 160ms + 120ms
        after(at):     plotOn(div.line, .5s)        // span extends; ticks then label appear

// 5 — IN PRODUCTION  (gate on scroll, not a fixed timer)
new IntersectionObserver(rows → row.reveal(), { threshold:.4 })
//   conceptually a GSAP ScrollTrigger; the live demo runs vanilla JS

// 6 — RESPECT THE USER
if prefers-reduced-motion:
    render one static frame (all entries shown, dividers fully drawn), no timeline
The "draw" primitive (reused everywhere): L = path.getTotalLength(); dasharray = L; dashoffset = L → 0. Each dimension-line span here uses the exact three lines that draw the Home spine and the Journey tower — so the whole site reads like one hand drew it.
