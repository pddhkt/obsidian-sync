# Open Questions

Answer these gradually. The website structure can be refined after the first five priority questions are clear.

## Positioning

- [ ] What should a visitor remember about you after 30 seconds?
- [ ] Is the first goal finding a software role, attracting freelance clients, meeting collaborators, or building a long-term public identity?
- [ ] Which roles are the current priority: frontend developer, full-stack developer, product engineer, technical founder, or another direction?
- [ ] How much should the structural engineering background appear in the main story?
- [ ] Should the public brand use "Jack", "Leung Man Hin", or both?

## Website scope

- [ ] Should the first version be English only or bilingual?
- [ ] Which pages are required for v1: Home, About, Projects, Writing, CV, Contact?
- [ ] Should app ideas be public, private, or selectively summarized?
- [ ] Do you want the website to feel like a portfolio, a personal notebook, or both?
- [ ] Which domain name do you want to use?

## Projects and confidentiality

- [ ] Which CTINT work can be described publicly?
- [ ] Can client names appear publicly, or should they be anonymized?
- [ ] Can Buddy Ride and Yeslend include screenshots, links, usage numbers, or technical diagrams?
- [ ] Which three projects best represent the work you want next?

## Content

- [ ] Which three themes do you want to write about first?
- [ ] Which channels matter first: website blog, LinkedIn, Instagram, Facebook, X, or another platform?
- [ ] Do you want short build notes, deeper essays, tutorials, product analysis, or a mix?
- [ ] What publishing rhythm is realistic?

## CV

- [ ] What role should the first tailored CV target?
- [ ] Should the CV emphasize software work only, or retain a compact structural engineering section?
- [ ] Which achievements can be supported with numbers or outcomes?
- [ ] Which public profile links should appear in the CV?
