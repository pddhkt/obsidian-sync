## 2）新網站係取代現有網站,定係引導去 Shopline?

新網站係 Imarflex **自己擁有、自己控制 brand image 嘅地方**,內建完整購物功能(自家 checkout,經 Airwallex 處理 FPS / AlipayHK / WeChat / 信用卡 / 分期)。

關於同 Shopline 嘅關係,有 **2 個 options** 俾 Imarflex 揀:

### Option A — 並行過渡(保留 Shopline 至合約期滿)

- 新網站即刻上線做主場,係 Imarflex 擁有自己 brand image 嘅地方,有完整購物功能。
- Shopline 繼續行,直至現有合約期滿先退役 —— 唔使蝕提早解約 / 違約成本。
- 兩個站獨立運作。
- 合約期滿後再做最終 migration,Shopline 正式落幕。
- 注意:過渡期兩個站並存,要留意產品 / 價格 / 庫存兩邊同步,SEO 上要設定 canonical 避免重複內容。

### Option B — 直接取代

- 一次過 migrate,Shopline 即時退役,只剩新網站。
- 最乾淨,無並行管理負擔。
- 前提:Shopline 合約容許提早結束,或已接近完約。

> **兩個 options 都唔會引導用戶去 Shopline。** 新網站本身有完整購物功能,唔會 link 客人去 Shopline 落單。

### 點樣 migrate?

無論揀邊個 option,最終都要做 migration。步驟:

1. **Pre-migration** —— audit Shopline 嘅 export 能力,確認可以匯出咩數據。
2. **匯出數據** —— 產品、分類、客戶名單、訂單紀錄。
3. **匯入新平台** —— 導入後逐項核對數量同內容正確。
4. **內容遷移** —— 產品描述、圖片、blog、政策頁等。
5. **設定 301 redirect**(見下文)。
6. **最終同步**(Option B)—— 上線切換期間短暫凍結 Shopline 落單,做最後一次數據同步。
7. **Post-migration** —— 上線後監察 1–4 週,核對訂單、付款、排名。

### 什麼是 301 redirect?點樣 implement?

**301 redirect = 「永久轉址」。** 當有人(或 Google)訪問一條舊網址,伺服器會自動、永久咁將佢帶去對應嘅新網址。

點解重要:換平台後網址結構會變,如果唔處理,舊網址會變 404(死連結),Google 累積落嘅排名亦會跌晒。301 會將舊網址嘅**搜尋排名權重「過戶」**去新網址,保住 SEO。

實作步驟:

1. Migration 前,export Shopline 所有現有網址清單(產品頁、分類頁、blog 頁)。
2. 為每一條舊網址,對應番新平台上同一內容嘅新網址,整一張 redirect 對照表。
3. 喺新平台 / 伺服器層設定 301 規則。
4. 上線後逐條測試舊網址正確跳轉,確認冇 404。
5. 更新 sitemap、提交 Google Search Console,監察排名 4 週,有問題即修。
