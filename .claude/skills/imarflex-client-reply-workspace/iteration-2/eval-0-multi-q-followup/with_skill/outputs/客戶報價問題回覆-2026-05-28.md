## A1)後台支持多 user + role permission — 你哋形容嘅 access control 做到

**做到 —— 後台一開始就係按 multi-user + RBAC(role-based access control)設計嘅。** 即係 Imarflex 可以開多個 user,每個 user 跟所屬 role 限定睇到 / 改到邊啲嘢。

簡單講,你哋舉嘅兩個例子:

- **客服同事得睇訂單但唔可以改價** —— 做到。set 做「客服 role」就只有訂單 + 客戶資料嘅讀寫權,產品價錢 / spec / catalogue 嗰邊鎖住唔顯示「編輯」掣。
- **Marketing 同事可以寫 blog 但唔可以改產品 spec** —— 都做到。set 做「Marketing role」就有 blog / 內容 / banner / promo 嘅讀寫權,產品 catalogue 嗰邊變 read-only。

### 預設 role(可即用)

| Role | 可以做 | 唔可以做 |
|---|---|---|
| **Owner / Admin** | 全部 —— 包括開 user、改 role、睇財務 reports | — |
| **Manager** | 全部日常操作(訂單、產品、內容、promo、reports) | 開 user / 改 role / 改公司結算資料 |
| **客服(Customer Service)** | 睇訂單、改訂單狀態、回覆客戶查詢、處理退換、睇會員資料 | 改產品價錢 / spec、寫 blog、改網站內容、睇銷售總額 reports |
| **Marketing / 內容** | 寫 blog、改 PDP 文案 / 圖、出 banner、設 promo code、睇 traffic reports | 改產品價錢 / 庫存、處理訂單、睇客戶私人資料 |
| **Viewer / 老闆 view** | 全部 read-only(包括 dashboard + reports) | 任何寫操作 |

### 自訂 role

如果上面 5 個 preset 唔啱用,後台有「自訂 role」嘅介面 —— 可以針對每個功能模組(訂單 / 產品 / 內容 / Promo / Reports / 設定)逐項揀「冇權 / 讀 / 讀+寫」。即係話將來 Imarflex 想加一個「淨係出 promo」嘅 role、或者一個「只睇某幾類產品」嘅 role,自己後台 set 到。

### 同 audit log 配套

每個寫操作都有 audit log —— 邊個 user、幾時、改咗咩 —— 後台有 history 頁可以查。**萬一有同事誤改,可以追返**。

> 想 confirm 一樣嘢:Imarflex 而家同事大概幾多人需要登入後台?分大概邊幾個崗位?(例如:1 個老闆 view、2 個客服、1 個 marketing、3 個產品部上架同事)—— 我哋按實際分組幫你哋預設好 role 同 invite,Imarflex 第一日上去已經分得清。

## A2)後台有「產品附件」section,PDP 自動顯示 PDF download — 做到

**做到 —— 後台每件產品都有「附件 / Downloads」section,可以上載任意數量嘅 PDF 文件,前台 PDP 自動顯示一個 download list 俾客戶 click。**

### 後台點操作

- 入去任何一件產品 → 「附件」section → 上載 PDF(用 drag-and-drop 或者揀檔案)。
- 每個附件可以填:
  - **顯示名稱**(例如「IMC-2019 使用說明書(繁體中文版)」)
  - **類別**(說明書 / 保養手冊 / 規格表 / 安裝指南 / 其他 —— 預設嘅,亦可以加新類別)
  - **語言**(繁中 / 英文 / 簡中,client 端會跟用戶語言優先顯示)
  - **檔案大小自動偵測**(顯示「2.4 MB」呢類俾客戶心理準備)
- 上載完即時生效,唔需要重新 publish 個產品。
- **可以一個產品掛多個 PDF** —— 例如同一件雪櫃可以同時掛「使用說明書」+「保養手冊」+「規格表」+「能源效益標籤」。

### PDP 點顯示

PDP 會喺產品描述下面有一個「**下載 / Downloads**」section,類似咁:

```
下載
─────────────────────────────────────
[PDF]  使用說明書(繁體中文)        2.4 MB    ↓ 下載
[PDF]  保養手冊                   1.1 MB    ↓ 下載
[PDF]  規格表                     480 KB    ↓ 下載
```

- 客戶 click 就直接 download,唔需要登入(因為 manual / 規格表本身應該公開易攞)。
- **PostHog 追蹤每個 PDF 嘅 download 數** —— 後台 reports 可以睇邊類 PDF 最多人 download、邊件產品嘅 manual 經常俾人攞 —— 反映客戶售後常見需求,可以用嚟 inform 之後嘅 FAQ / blog 內容方向。

### 文件管理

- 所有上載嘅 PDF 統一放喺後台「**媒體庫 / Documents**」section,亦可以唔經產品頁直接 upload 一批,之後再 link 落唔同產品(例如同一份「保養條款」可以 link 落幾十件產品,改一次就全部更新)。
- 預設容量 10 GB(每個檔最大 25 MB)—— 對 Imarflex 嘅產品 manual 量嚟講綽綽有餘。超出嘅話再傾,正常用唔到。

## A3)澳門 cross-border — 架構預咗,實際擴展屬 Phase 2 另議

**做到,但要分階段講清楚 —— 因為 cross-border 唔單止係技術問題,亦涉及 legal / tax / 物流嘅落地細節。**

### Phase 1(現時報價內已經包嘅嘢)—— 「擴展 ready」架構

而家起新網站嘅時候,以下基礎已經幫 Imarflex 預咗,將來擴展澳門唔需要重做架構:

- **Multi-currency-ready 嘅產品 schema** —— 每件產品價錢欄唔係寫死「HK$」,而係結構化嘅 `{ currency, amount }` 設計。將來加 MOP(澳門幣)只需要喺後台多輸入一欄價,前台會跟用戶所在地或者用戶手動揀嘅 currency 顯示。
- **可擴展嘅地址 schema** —— checkout 地址欄唔係寫死香港(區 / 大廈 / 街),而係按國家 / 地區動態 render —— 將來加澳門地址格式(街 / 巷 / 門牌 / 樓層,冇「區」概念)只需要加一個地區 config,唔需要改 checkout code。
- **Shipping zone 引擎** —— 後台已經有「shipping zone」概念,而家得「香港」一個 zone,但架構支援將來加「澳門」zone(對應唔同運費 rate、不同物流商、不同 cut-off time)。

呢三樣嘢屬於「預咗位但未填內容」—— 唔加錢,因為今日就要起對嘅架構,將來唔使返工。

### Phase 2(真正擴展澳門嘅時候)—— 屬另議範圍

當 Imarflex 真正準備好行澳門嘅時候,以下工作要做,屬另一個 scope:

| 工作項目 | 內容 |
|---|---|
| **MOP 顯示 + 匯率設定** | 後台設 HKD / MOP 對換比例,或者鎖死 1:1.03(實際業務決定)。Airwallex 支援 MOP 收款 —— 確認支援後可以直接收。 |
| **澳門地址格式** | 加澳門地區 / 街道 config,checkout 自動切換。 |
| **澳門 shipping 設定** | 揀物流商(順豐 / 跨境快遞 / 其他)、設運費表、設 cut-off time、揀邊啲產品適合運(例如大型家電 vs 小型) |
| **澳門退換 / 保養條款** | 一份新嘅 policy 頁(中 + 葡 / 中 + 英)cover 澳門法律差異 |
| **客戶 IP / 語言偵測 + 引導** | 澳門 IP 入嚟自動 toast「想睇澳門版?」(類似 Apple HK / Apple Macau 嘅 pattern) |

實際 scope 同價錢要等 Imarflex 業務細節清晰啲先報得實 —— 例如:係淨係收澳門落單香港寄,定係本地 stock?係淨係 D2C,定係要連澳門實體 / 經銷?呢啲決定影響做幾深。

### 坦白講

**澳門 cross-border 嘅 legal / tax / 報關層面唔係我哋強項。** 我哋可以做技術側嘅嘢(currency、地址、checkout、運費邏輯),但澳門:

- **稅務處理**(澳門無 VAT 但有消費稅 / 牌照要求)
- **跨境物流報關**(申報價值、HS code)
- **澳門公司註冊需要 / 退換法律差異**

呢類嘢建議搵**澳門本地會計師 + 跨境物流 partner** 確認合規 —— 我哋技術側配合,但唔代客做合規判斷。
