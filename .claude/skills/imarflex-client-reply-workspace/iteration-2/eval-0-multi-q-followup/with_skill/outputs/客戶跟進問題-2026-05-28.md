## A. 網站 / 後台相關跟進

### A1）後台支唔支持多 user 同 role permission?
> 「個試用 admin 啱啱試咗,想知支持唔支持多 user 同 role permission?例如客服同事得睇訂單但唔可以改價,marketing 同事可以寫 blog 但唔可以改產品 spec — 呢類 access control 做唔做到?」

### A2）後台有冇位上載 / 管理產品 PDF(說明書 / 保養手冊),喺 PDP 顯示俾客戶 download?
> 「我哋部分產品有 PDF 說明書同保養手冊,客戶買咗會想自己 download。新後台有冇位俾我哋上載同管理呢類 PDF 文件,然後喺 PDP 顯示俾客戶?」

### A3）中長期擴展去澳門 cross-border — 同一個 site 處理 currency / 地址格式 / 運費邏輯做唔做到?
> 「中長期我哋想擴展去澳門做 cross-border,同一個 site 處理唔同 currency / 地址格式 / 運費邏輯做唔做到?」

### 對齊決定

| # | 問題 | 方向 |
|---|---|---|
| A1 | 多 user + role permission | 做到,custom CMS 已預咗 RBAC;列預設 role(Owner / Manager / 客服 / Marketing / Viewer)+ 自訂 role;包喺現有 build,唔額外收費;邀請 Derek confirm 同事分組 |
| A2 | 產品 PDF 上載 + PDP 顯示 | 做到,後台「產品附件」section;每個 PDP 可掛多個 PDF(說明書 / 保養手冊 / 規格表),分類顯示 + download tracking(PostHog);包喺現有 build |
| A3 | 澳門 cross-border | 做到,但分階段:Phase 1(現時報價內)已預咗 multi-currency-ready 架構 + 地址 schema 可擴展;Phase 2 (擴展澳門時)做實際嘅 MOP 顯示 / 澳門地址格式 / 運費 zone / 稅務 → 另議,先 outline scope 唔報死數;誠實講澳門 cross-border legal / tax 唔係我哋強項,建議搵當地會計同物流 partner 確認合規 |
