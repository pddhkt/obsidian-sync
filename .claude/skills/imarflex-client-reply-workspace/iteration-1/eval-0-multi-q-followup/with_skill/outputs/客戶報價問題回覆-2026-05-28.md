## A1)多 user 同 role permission — 後台內置 RBAC,做到

**做到 —— custom CMS 入面已經 build 咗 role-based access control(RBAC,即係按角色分權限),Imarflex 可以開幾多個同事 account 都得,每個 account 屬一個 role,role 決定佢可以睇 / 改邊啲嘢。**

### 預設已經 set 好嘅 3 個 role

| Role | 可以做 | 唔可以做 |
|---|---|---|
| **Admin**(管理員) | 全部 —— 用戶管理、產品、訂單、價錢、Blog、設定 | (冇限制) |
| **客服(Customer Service)** | 睇訂單、改訂單狀態(確認 / 出貨 / 退換)、回覆客戶查詢、睇客戶資料 | **改價、改產品 spec、改 Blog、刪訂單** |
| **Marketing** | 寫 / 改 Blog、上新最新消息、改 banner、整 promo landing page、睇分析數據 | **改產品 spec / 價錢、改訂單、睇客戶個人資料** |

> Derek 提到嘅兩個 case —— 客服得睇訂單唔可以改價、Marketing 寫 blog 但唔可以改產品 spec —— **正正係上面預設 role 嘅 default 行為**,即裝即用,唔需要額外設定。

### 想再細啲分都得

如果 Imarflex 想再 fine-tune(例如想分「初級客服(只可以睇)」vs「資深客服(可以改訂單狀態)」),我哋可以:

- **加新 role + 自訂權限 matrix** —— 邊個 module、邊個 action(view / create / edit / delete)分別 toggle。
- **Per-module 鎖** —— 例如某個產品系列只俾特定同事改。

呢類自訂 role 設定 **包喺 3.1 月度 retainer 內**,通知我哋話想點分,我哋幫手 set 好。

### 安全 / 操作記錄

- **每個 user 獨立 login**(唔好幾個人 share 同一個 account),日後追責任 / 查紀錄會清楚好多。
- **操作 log:** 後台會記低邊個 user 喺幾時改咗咩(例如「Mary 喺 14:32 將 IRC-20IH 價錢由 $1,580 改成 $1,480」),日後要 audit 或者出咗事追原因都揾得返。
- **2FA(雙重認證)可以開** —— 建議至少 Admin role 嘅 account 開,passcode 經 Google Authenticator / SMS 收。

> 想 confirm 一樣嘢:Imarflex 想預先開幾多個 user account?同邊啲同事 map 邊個 role?可以 send 一張 list(同事名 + email + role)俾我哋,我哋連同試用環境一齊 set 好。

## A2)PDF 說明書 / 保養手冊 — 後台有文件管理位,PDP 自動顯示

**做到 —— 後台入面有「產品文件管理」section,可以上載 PDF(或者 doc / 圖片)、tag 去對應產品,PDP 會自動喺一個固定位置(預設係規格表下面)顯示「相關文件下載」section 俾客戶 click 下載。**

### 後台點 work

- 入產品編輯頁 → **「相關文件」tab** → upload PDF → 填個顯示名(例如「IRC-20IH 使用說明書」/「保養手冊」/「快速使用指南」)→ 儲存。
- 一個產品可以掛**多份文件**,可以排序(例如說明書排第一,保養手冊第二)。
- 同一份文件**可以 share 比多個產品**(例如同系列產品共用一份保養條款),唔需要重複上載。
- 改 / 換 / 刪文件隨時做到 —— 換新版本就 re-upload 同名文件,舊 link 自動 redirect 去新版本,**已經分享出去嘅舊 URL 唔會壞**。

### 客戶喺 PDP 睇到嘅樣

- 一個簡潔 list:**文件 icon + 顯示名 + 檔案大小**(例如「使用說明書 PDF · 2.4MB」)。
- Click 即 download(或者手機上直接喺 browser 開)。
- 如果想要,**可以加埋「需要登入會員先 download」**嘅 gating —— 想將 PDF download 當 lead magnet 收 email,可以開呢個 option。
- **無痛配合保養登記:** 客戶 download 保養手冊嗰陣可以順手 prompt「順便登記保養?」—— 一個 download 行為帶兩個用途。

### 包唔包?

- **建置:** 包喺新網站本身,**唔額外收費**。
- **持續上載 / 更新文件:** 同事自己後台做 (建議由 Marketing 或 Admin role 做),**或者通知我哋代做** —— 兩樣都包喺 **3.1 月度 retainer**,屬「日常內容更新」範疇。
- **存儲 / 流量:** 用我哋現有 Cloudflare R2 storage,Imarflex 唔需要另租 server / 另畀 storage 費。

> 想 confirm 一樣嘢:Imarflex 而家手上大約有幾多份 PDF?(粗略數目就得,例如「30–50 份」)—— 如果係**大批量初次上載**,我哋可以一次過幫手 batch upload + tag,當 onboarding 一部分,慳同事時間。

## A3)澳門 cross-border — 架構支持,坦白分而家 build 同之後加嘅嘢

呢條問得啱時候 —— **新網站架構由 day 1 已經考慮多 region**,所以技術上唔需要日後重做。但要分清楚:**「技術架構支持」≠「即日可以喺澳門賣嘢」**,中間有幾層運營層嘅嘢要決定。**坦白講分開講會清楚啲。**

### 技術層 —— 而家 build 入面已經做到

| 範疇 | 點 work |
|---|---|
| **多 currency** | 同一個產品可以同時顯示 HK$ + MOP$;客戶喺網站可以揀地區 / 自動 detect IP,價錢、checkout、發票都跟。Currency rate 可以鎖死(例如 1 HKD = 1 MOP 平手定價)或者跟外匯浮動,二揀其一。 |
| **多地址格式** | Checkout 地址表單可以按地區切換 —— 香港用「區 / 大廈 / 樓 / 室」,澳門用「街道 / 大廈 / 樓層」,validation rule 各自處理。 |
| **多運費邏輯 / Shipping zone** | 後台可以開幾多個 shipping zone 都得 —— 香港島 / 九龍 / 新界 / 離島 / **澳門** 各自一個 zone,每個 zone 可以 set 唔同運費 logic(免運門檻、按重量、按件數、flat rate)。 |
| **多語言 ready** | 而家先做繁中,但架構支持加簡中 / 英文 —— 之後想加只係**內容工作**,唔需要重 build。 |
| **多 payment method** | Airwallex(現有 payment provider)本身支援 MOP 結算同澳門發行嘅卡,後台 enable 就得;另外 AlipayHK / WeChat Pay 喺澳門都通用。 |

> 即係話:**澳門客戶上嚟,可以見到 MOP 價錢、填澳門地址、計澳門運費、用佢哋熟悉嘅 payment method 結帳。** 呢部分包喺現有報價內,**唔額外收費** —— 開 zone + set rate + enable currency,**屬 3.1 retainer 內嘅 config 工作**。

### 運營層 —— 真正開賣前要決定 / 唔屬我哋 scope 嘅嘢

**坦白講,呢部分唔係我哋強項**,但要 flag 出嚟,免得 Imarflex 將來踩到先發覺:

- **跨境物流:** 香港寄澳門用邊間 courier(SF / 順豐 / 嘉里 / 自取點)、清關手續、申報價值上限 —— 屬物流 partner 嘅範疇。後台運費 logic 我哋幫手 wire 好,但**揀邊間物流 / 簽合約唔屬我哋 scope**。
- **跨境稅務 / 報關:** 澳門對某啲類別嘅家電有進口管制 / 稅,要同會計師或者熟悉澳門法規嘅 partner 確認 —— 唔係 web 嘅問題。
- **澳門公司實體 / 收款戶口:** 想長線做澳門市場,可能要考慮喺澳門開 entity / MOP 收款戶口(Airwallex 都做到 multi-currency settlement,但係咪夠用要睇 Imarflex 規模)。
- **客服語言 / 時段:** 澳門客戶用繁中冇問題,但客服同事邊個 cover、有冇 WhatsApp 澳門號等,屬人手安排。

### 點建議走

1. **而家(網站 launch 階段)** —— 唔需要做任何嘢,架構已經 ready,將來 enable 就得。
2. **想 soft-launch 澳門(中期,例如 launch 後 3–6 個月)** —— 通知我哋,我哋一星期內 enable 澳門 zone + MOP 顯示 + Airwallex MOP 收款,**屬 3.1 retainer config 工作,唔加錢**。
3. **想正式做澳門市場(長期)** —— 之前提嘅運營層問題要先 sort:物流 partner、稅務、語言 / promo 策略。呢個層次 Imarflex 可能想另外搵熟悉跨境電商嘅顧問;**唔係我哋強項,我哋唔扮專家。**

> 想 confirm 一樣嘢:Imarflex 對澳門擴展嘅 timeline 大約點?(「6 個月內試水」vs「1–2 年後再諗」)—— 唔同 timeline 影響我哋而家要唔要預先打底定純 architecturally ready 就算。
